# Raw results — R-19, DynLex runtime performance against C++

Generated by `harness.py`. Every number in `FINDINGS.md` comes from a row here.

Runs per binary: 5; the reported figure is the median.

The binaries of one workload are run round-robin, one each per round, so that
background load on the machine falls on both languages equally rather than being
attributed to whichever ran first. orient3d and prng_only are the exception: their
six binaries (both workloads, all three tags) are interleaved together in one
round-robin, so the PRNG-subtracted derivation below is not confounded by drift
between two separately-timed sessions (finding I1).


## Timed region, per workload (finding I1)

What each workload's `started .. finished` clock window actually covers —
stated explicitly because for two of the four it is *not* the arithmetic alone:

| Workload | Timed region |
|---|---|
| Triangle/triangle, 1e6 pairs | generation (6 random points per pair) + the edge-wise Moeller-Trumbore test |
| BVH build, 1e6 boxes | the build only; box generation (and the PRNG) is outside the timed region |
| orient3d f64, 1e7 quadruples | generation (4 random points per quadruple) + the orient3d determinant |
| PRNG-only baseline, 1.2e8 doubles (finding I1) | generation only (4 random points per iteration, no arithmetic on them) — isolates the PRNG share of tritri/orient3d |

## Derived: PRNG-subtracted orient3d (finding I1)

orient3d's timed region is generation *and* the determinant (see the timed-region
table above); its 1.01x whole-workload ratio is therefore a mixed
figure, not a determinant-only one. `prng_only` draws the identical 4 sample points (12 doubles)
per iteration and does nothing else, so `orient3d - prng_only`, done per language,
is a *derived* estimate of the determinant-only cost. Both figures below come from
the SAME interleaved measurement round (see the note above the timed-region table),
so machine-load drift cancels rather than leaking into the subtraction.

| | DynLex -O2 ms | C++ -O2 ms |
|---|---:|---:|
| orient3d (generation + determinant) | 155 | 153 |
| prng_only (generation only) | 146 | 145 |
| **derived: determinant only** (orient3d − prng_only) | 9 | 8 |

**Derived determinant-only ratio: 1.12x.**
 This does not exceed the 1.5x line.

## Clock calibration

The workloads report their own timings in milliseconds on the assumption that libc
`clock()` ticks at 1000 Hz on this toolchain. `clock_calibration.dl` checks that
assumption against an external stopwatch: a fixed-result loop, timed both by
`clock()` and by `time.perf_counter` around the process with the empty-program
baseline subtracted. `CLOCKS_PER_SEC` is 1000 if the last column reads about 1000.

One run per line, in order. Readings converge on 1000 from below as the runs
settle: a low reading is the external stopwatch running longer than the tick
count, which is what a descheduled or cold-started process looks like.

## Default build check (finding M2)

`dynlex file.dl -o out` with **no** optimisation flag at all, compiled and run,
compared against the explicit `-O0` build of the same source. If the two binaries'
md5 match, the no-flag build and the `-O0` build are the same compiler output, not
merely two runs that happen to agree — which is stronger evidence than a timing
comparison for "the compiler's default is -O0".

| | |
|---|---|
| Source | `orient3d.dl` |
| Compile time, no flag | 0.3 s |
| md5, no flag (raw) | `401dfb571f14fa6a6e1ba0de6e28f790` |
| md5, explicit `-O0` (raw) | `6e4933e2e7c68519698334141a240a39` |
| Binaries byte-identical (raw) | **False** |
| No-flag run answers | 5002121 \| 59995750.315272383 \| -2012412911526409390 |

The raw md5 need not match even for identical emitted code: `lld` embeds a PE COFF
`TimeDateStamp` (the build clock, in seconds) and the two builds run a few seconds
apart. So the harness also zeroes every 4-byte span in each binary that is
byte-identical to that binary's own COFF timestamp field — `lld` was observed to
duplicate the value elsewhere in the image, not just in the COFF header — and
rehashes. This is the code-identity check; the raw md5 above is the honest,
unmassaged one.

| | |
|---|---|
| COFF TimeDateStamp, no flag | `1789201403` |
| COFF TimeDateStamp, explicit `-O0` | `1789201401` |
| Timestamp delta | 2 s |
| Timestamp occurrences neutralised, no flag | 2 at byte offsets [128, 13828] |
| Timestamp occurrences neutralised, `-O0` | 2 at byte offsets [128, 13828] |
| md5, no flag (timestamp-neutralised) | `628aedf128a5219d0824a28fc5f8247b` |
| md5, explicit `-O0` (timestamp-neutralised) | `628aedf128a5219d0824a28fc5f8247b` |
| Binaries byte-identical (timestamp-neutralised) | **True** |
